# Развёртывание Telegram-бота на Render Free

Эта копия подготовлена для Docker Web Service и Telegram webhook. Dockerfile устанавливает `ffmpeg`; Gunicorn запускает Flask-приложение; при старте бот автоматически берёт публичный URL из переменной Render `RENDER_EXTERNAL_URL` и регистрирует webhook. Токен и база PythonAnywhere в эту папку не копировались.

## 1. Загрузить проект в GitHub

Создай **приватный** репозиторий GitHub. Загрузи содержимое этой папки так, чтобы `Dockerfile`, `render.yaml`, `requirements.txt`, `main.py` и `web_app.py` находились в корне репозитория.

Не загружай настоящий `.env`, каталог `.data`, журналы или SQLite-файлы. В этом комплекте они отфильтрованы `.gitignore` и `.dockerignore`. Не вставляй токен в исходники или GitHub.

## 2. Создать сервис Render

В Render выбери **New → Blueprint**, подключи GitHub и укажи приватный репозиторий. Render прочитает `render.yaml` и создаст бесплатный Docker Web Service. Если во время создания появится поле `TELEGRAM_BOT_TOKEN`, вставь туда новый токен, полученный у `@BotFather` после отзыва старого. Переменная `TELEGRAM_WEBHOOK_SECRET` генерируется автоматически.

Приложение само приводит сгенерированный secret к допустимому для Telegram формату; вручную создавать webhook URL не нужно.

Дождись завершения сборки и первого запуска. Сервис слушает порт, который Render передаёт через `PORT`. В `render.yaml` для health check используется `/healthz`, не зависящий от ответа Telegram API.

## 3. Проверить webhook и бота

Открой адрес сервиса Render с путём `/health`. После успешной регистрации ожидается JSON со `status: "ready"` и `webhook_registered: true`. Затем отправь боту короткую тестовую ссылку. Логи приложения доступны в панели Render в разделе **Logs**.

Если `/health` показывает `registering` или `registration_error`, проверь, что в Render задан правильный новый токен. Затем посмотри Render Logs. Не публикуй логи или токен в открытом GitHub.

## Ограничения бесплатного плана

Render Free может усыпить сервис после 15 минут без входящего трафика. Пробуждение может занять около минуты, поэтому первый ответ после долгого простоя иногда задерживается.

По просьбе владельца счётчик лимитов пока остаётся в локальной SQLite-базе по пути `/tmp/request_limits.sqlite3`. На бесплатном Render локальные файлы непостоянны, поэтому счётчик может обнулиться после сна или перезапуска. Это не влияет на сообщения и видео, уже отправленные в Telegram; оно влияет только на внутренний лимит запросов бота.
